### 1. 주제·배경·기대 효과 (01 개요)
- **메시지**: 치료사가 하던 반복 던지기·받기 훈련을 로봇이 파트너가 되어 대신한다.
- **본문**
  - 상지 재활은 같은 동작을 수백 번 반복해야 하는데 치료사 1명이 환자 1명에게 붙어 있어야 함.
  - RALLY = 두산 M0609 + RG2 그리퍼 + RealSense 로, 공·패드·컵 같은 **물체를 통해** 환자와 상호작용하는 상지 재활 파트너 로봇.
  - 로봇이 환자 쪽으로 능동적으로 미는 동작은 설계에 없음 (안전 원칙).
  - 기대 효과: 치료사 1명이 여러 환자 세션을 대시보드로 보며 운영. 시도마다 수치(오차·시간·힘·보상 동작)가 DB 에 쌓이고 세션 끝에 리포트(수치 요약 + LLM 해석)가 자동 생성. 영상 원본은 외부로 안 나가고 LLM 에는 화이트리스트 수치만. 음성은 호출어 뒤 녹음만 STT 를 위해 OpenAI 로 보내고, 비상어 감지는 로컬.
- **그림**: 작업대 일러스트 (환자 자리에서 로봇을 본 구도).
- **출처**: `CLAUDE.md` 1·4절, `docs/RALLY_기획서.md`, PR #121(세션 리포트), #103(화이트리스트).
- **멘트**: "랠리"는 탁구의 랠리처럼 주고받는 것. 주고받는 것 자체가 훈련이다.

### 2. 특화 포인트 — 랠리 4모드 (01 개요)
- **메시지**: 난이도가 다른 4가지 상호작용을 한 로봇이 한 세션에서 이어 간다.
- **본문** (모드당 한 줄)
  - 모드 1 가이드 길 공 굴리기 — 로봇이 레인 입구에서 공을 쳐 환자 손 쪽으로 보냄, 환자가 받음.
  - 모드 3 던진 공 받기 (챌린지) — 환자가 3 m 에서 던진 벨크로 공을 로봇이 쥔 패드로 받음.
  - 모드 5 기울인 물체 건네고 받기 — 로봇이 막대를 무작위 기울기로 건네고, 환자가 돌려주면 받음.
  - 모드 7 저항 밀기 — 환자가 로봇 손목을 밀고, 로봇이 버티다 져줌 (유일하게 물체 없이 손목을 직접 미는 예외).
  - 세션 흐름: 모드 1 → 3 → 5 → 7, 모드 3 은 설정으로 켜고 끔.
- **수치**: 시도 수 — 모드 1 은 거치대 공 4개, 나머지 모드당 5회 (DEMO_CHECKLIST 6절).
- **그림**: 4모드 아이콘·한 줄 그림.
- **출처**: `CLAUDE.md` 1절, `docs/DEMO_CHECKLIST.md` 6절, PR #157(모드 7 손목 직접 밀기 결정).

### 3. 기술 스택 — 무엇을 어디에 왜 (01 개요)
- **메시지**: 기술마다 맡은 계층이 있고, 고른 이유는 "안전·지연·분리" 셋이다.
- **장비**: 두산 M0609 · OnRobot RG2 · RealSense 2대(손목 eye-in-hand + 측면, 측면은 모드 3) · 측면 웹캠(몸 자세) · PC 2대(로봇·인식 PC GPU / 서버 PC).
- **본문 (표 하나)**
  | 계층 | 기술 | 쓰인 곳 | 고른 이유 |
  |---|---|---|---|
  | 로봇 제어 | 두산 DRL · ROS 2 Jazzy(Python 3.12) | `rally_robot` 스킬 서버(액션 8개), 순응 제어 | 접촉 구간 힘 제어, 스킬을 액션으로 감싸 판단과 분리 |
  | 안전 | 독립 노드 `safety_monitor` + `safety.yaml` | 손 거리·힘 25 N·작업 공간·입력 누락·nudge | 판단·LLM 과 무관하게 로봇 PC 에서 100 Hz 로 직접 멈춤 |
  | 비전 | YOLO-Seg(ultralytics) + TensorRT, EKF·타임스탬프 궤적 맞춤 | 공·컵·막대 3D, 모드 3 던진 공 예측 60 Hz | 깊이 카메라 eye-in-hand, 두 카메라 한 배치 추론 |
  | 사람 인식 | MediaPipe 손·몸 자세 | 손 ↔ 로봇 거리, 레인 선택, 보상 동작 20° | 21점 손 랜드마크 + 깊이로 거리, 실시간 |
  | 음성 | openWakeWord 백본 + 전이 학습 판별기, STT(OpenAI), Piper TTS | 비상어·호출어 "랠리야", 안내 음성 | 비상 정지는 STT·네트워크 없이 80 ms 판정 |
  | 판단 | py_trees 행동 트리 · 규칙 레이어 · gpt-4o(격리) · 온톨로지·Graph RAG | 세션 흐름, 난이도, 휴식 제안, 리포트 | 규칙 우선(#78), LLM 은 애매한 판단·설명만 |
  | 데이터 | PostgreSQL + TimescaleDB + pgvector, Redis | 시도·세션·사건, 힘 시계열, 유사 시도, 실시간 상태 | 시계열·관계·벡터를 한 DB 에, 영상 저장 안 함 |
  | HMI | FastAPI + WebSocket | 대시보드(상태·단계 그림·카메라·휴식 제안·모드 전환) | ROS 없이 Redis 로 brain 과만, 로봇 직접 명령 없음 |
  | 인프라 | Docker compose(pc2·pc3), Fast DDS Discovery Server | 추론·서버 컨테이너, 두 PC 연결 | 의존성 충돌 분리, 서버 PC 는 두산 SDK 없이 |
  | 시뮬레이션 | Isaac Sim 디지털 트윈 + PPO | 모드 3 출발 시점·보정량 정책 | 실측 반영 트윈에서 학습, 실로봇은 규칙 폴백 |
- **수치**: 인터페이스 — msg 8 · srv 6 · action 8 (`CLAUDE.md` 3절). ROS 패키지 8개(interfaces · bringup · robot · vision · human · voice · brain · db) + docker + dashboard.
- **그림**: 표 왼쪽에 계층 아이콘, 하드웨어 사진 한 장.

### 3-1. 프로젝트 구조 — 2 PC · 4계층 (01 개요, 양식 "프로젝트 구조")
- **메시지**: 인식 → 판단 → 스킬 → 안전 네 계층을 두 PC 에 나눠, 안전은 판단과 떨어진 로봇 PC 에서 스스로 멈춘다.
- **본문 (구조도 한 장)**
  - 로봇·인식 PC (GPU)
    - `pc1` 네이티브: 두산 드라이버 · force_publisher · gripper · **safety_monitor**(독립, 100 Hz) · skill_server(PushBall · Handover · ResistPush · CatchBall …)
    - `pc2` 컨테이너: vision(RealSense ×2, YOLO-Seg, 예측기) · hand_pose·body_pose(MediaPipe) · voice(비상어·호출어·STT·TTS)
  - 서버 PC
    - `pc3` 컨테이너: brain(context_builder 상황판 5 Hz · bt_runner 행동 트리·규칙 · 휴식 판단·리포트 gpt-4o 격리) · db(PostgreSQL·Timescale·pgvector·지식 그래프) · redis · dashboard
  - 두 PC 사이: Fast DDS Discovery Server(서버 PC), QoS 센서 BestEffort · 안전·명령 Reliable · estop·speaking TransientLocal.
  - 데이터 흐름: 카메라·마이크 → 인식 토픽 → 상황판 → 행동 트리·규칙 → 스킬 액션 → 두산 DRL, safety_monitor 가 항상 감시.
  - 왜 이렇게: GPU 가 한 대라 카메라 → 인식 → 로봇 경로를 한 PC 에(지연·대역), 판단·DB 는 두산 SDK 없이 서버 PC 에(10/6 결정).
- **그림**: 두 PC 박스 + 가운데 Discovery Server, 화살표로 데이터 흐름 (아티팩트 "RALLY PC 구성도").
- **출처**: `CLAUDE.md` 1·3·5절, `docs/INTERFACES.md`, `docker/docker-compose.yml`.
- **멘트**: 7장은 같은 구조를 "한 시도가 지나가는 순서"로 다시 본다.

### 19. 성현 ① 강화학습 — 챌린지·접근 (04-C, 결과 제시 ⑬)
- **챌린지**: "언제 출발할지"는 예측 정확도(기다릴수록 좋음)와 이동 시간(빨리 갈수록 좋음)의 트레이드오프. 규칙 하나로는 투구마다 최적이 다르다.
- **접근**
  - 강화학습은 칼만·해석적 제어기를 대체하지 않는다. **출발 시점과 보정량(±10 cm)만** 정책이 정하고, 클램핑·품질 게이트·안전은 규칙과 같다 (#78 규칙 우선).
  - Isaac Sim 디지털 트윈에 실측(가속별 도착 시간·힘, servol 포화, 자기충돌 한계)을 반영 → PPO 1단계 학습 → ONNX 로 내보내 `catch_ball` 의 `decide_mode: policy` 로 실행 (기본은 rule).
  - 관측 obs[10] 은 시뮬과 같은 순서·배율. 50 Hz 로 0.10~0.40 s 동안 정책을 부르고 `action[0] > 0` 이 처음 나오는 순간 출발. 0.40 s 까지 안 나오면 규칙으로 폴백.
  - 2단계(servol 연속 추종)는 1차 지연 60~90 ms + 속도 포화 0.2 m/s 모델로 설계만.

### 23. 정묵 ① 휴식 제안 — 챌린지·접근 (04-C, 결과 제시 ⑰)
- **챌린지**: 환자가 "힘들어"라고 말하면 쉽지만, 말 없이 보상 동작만 늘거나 느려지는 피로는 애매하다. LLM 에 통째로 맡기면 안전·개인정보 문제, 규칙만 쓰면 오판.
- **접근 (규칙 → LLM 두 단계, #78 규칙 우선)**
  - 시도가 끝날 때마다 규칙 레이어가 행동 하나를 고름. 순서: 안전 STOP → 대기(코드 고정) / 음성 "힘들어" → **묻지 않고 바로 휴식**(현재 시도 마친 뒤) / 음성 어렵게·쉽게 / 3연속 성공 → 어렵게, 2연속 실패 → 쉽게 / **애매한 신호 2개 이상 → LLM** / 그 외 계속.
  - 애매한 신호 3개: **보상 동작 반복**(정동휘 body_pose 가 팔 뻗는 동안 몸통 기울임·어깨 들림 20° 이상 → 시도별로 기록, 같은 모드 최근 5회 중 3회 이상, #190), 성공률 40 % 이하(최소 3회), 직전 시도가 앞선 평균의 1.5배 이상 느림. 하나만으로는 행동을 안 정함.
  - LLM 호출: 보내는 건 같은 모드·난이도 최근 5회의 수치(모드·시도·성공·오차·시간)와 신호 불리언뿐(화이트리스트 `llm.yaml`). 답은 `continue`/`suggest_rest` 둘 중 하나, pydantic 검증, 비동기 작업자 하나, 3 s 타임아웃 → 규칙 폴백.
  - 기다리는 동안 STOP·취소·모드·난이도 변경이 생기면 돌아온 답을 폐기. 제안은 TTS "혹시 피곤하진 않으세요? 조금 쉬었다 할까요?" + 대시보드 20 초 카드, 사용자가 수락해야 현재 시도 마친 뒤 쉼. 기다리는 동안 훈련은 계속, 로봇을 직접 멈추지 않음.
- **수치**: 규칙 임계 — success_streak 3, failure_streak 2, llm_signal_count 2, success_drop_rate 0.4, slowing_ratio 1.5, compensation_window 5·compensation_min_trials 3 (`skills.yaml brain`, `rule_layer.py DEFAULTS`). 타임아웃 3.0 s, 이력 5회 (`llm.yaml`). 보상 동작 임계 20·20° (#102 #110).
- **그림**: 규칙 순서도 + LLM 격리 경계(무엇이 들어가고 무엇이 안 들어가는지).
- **출처**: `rally_brain/rule_layer.py`, `rally_bringup/config/llm.yaml`, PR #62 #83 #90 #94 #103 #110 #190, 이슈 #78.
